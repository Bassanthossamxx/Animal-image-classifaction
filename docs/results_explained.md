## 4. `training_curves.png`

### What it is

This figure is generated by Notebook 2.

It contains two plots:

- training loss and validation loss
- training accuracy and validation accuracy

---

### Why this file is important

This is one of the best ways to understand model behavior during training.

It answers questions like:

- Did the model learn at all?
- Did performance improve over epochs?
- Did overfitting start?
- Did early stopping make sense?

---

### How to read the loss curve

#### Good pattern

- training loss goes down
- validation loss also goes down or stays stable

This suggests the model is learning useful features.

#### Overfitting pattern

- training loss keeps going down
- validation loss stops improving or starts rising

This suggests the model is memorizing training data instead of generalizing.

That is exactly why your notebook used early stopping.

---

### How to read the accuracy curve

#### Good pattern

- training accuracy rises
- validation accuracy also rises and remains reasonably close

This means the model is learning and validation performance supports it.

#### Warning pattern

- training accuracy becomes extremely high
- validation accuracy stays much lower

This suggests overfitting.

---

### How to talk about your plot

You can say:

“Training curves showed consistent improvement in both loss and accuracy, while validation monitoring helped identify the best checkpoint and reduce overfitting risk through early stopping.”

## 5. `classification_report.txt`

### What it is

This is the main text summary of test performance generated in Notebook 3.

It contains:

- overall accuracy
- per-class precision
- per-class recall
- per-class F1-score
- support per class
- macro average
- weighted average

---

### What each metric means

#### Accuracy

Accuracy is:

```text
correct predictions / total predictions
```

It gives the overall percentage of correct classifications.

In your result:

- Accuracy = `97.56%`

That means the model predicted most test images correctly.

---

#### Precision

Precision answers:

“When the model predicts a class, how often is it correct?”

High precision means the model does not often make false positive mistakes for that class.

Example:

- Deer precision was `0.8889`

This means some image predicted as deer was actually another class.

---

#### Recall

Recall answers:

“Of all the real images in this class, how many did the model correctly find?”

High recall means the model rarely misses that class.

Example:

- Cat recall was `0.8824`

This means some real cat images were predicted as another class.

---

#### F1-score

F1-score combines precision and recall into one metric.

It is useful when you want one balanced score per class.

If either precision or recall is weak, F1 will also drop.

---

#### Support

Support is the number of true test examples for that class.

This helps you understand how much data each metric is based on.

In small test sets, one or two errors can noticeably change the score.

---

### Macro average

Macro average gives equal importance to each class.

This is useful when you want class-level fairness in the evaluation summary.

Your macro metrics are strong:

- Macro precision: `0.9778`
- Macro recall: `0.9765`
- Macro F1-score: `0.9757`

---

### Weighted average

Weighted average also uses class support sizes.

It gives slightly more importance to classes with more test samples.

In balanced or near-balanced datasets, macro and weighted averages are often similar.

---

### Overall interpretation

Your classification report shows excellent performance.

Strong points:

- very high overall accuracy
- most classes achieved perfect precision and recall
- macro metrics are consistently high

Minor weakness:

- cat recall is not perfect
- deer precision is not perfect

These are still small errors, not major failures.

## 6. `confusion_matrix.png`

### What it is

This is the confusion matrix heatmap produced in Notebook 3.

It shows the relationship between:

- true labels
- predicted labels

---

### How to read it

- Rows = true class
- Columns = predicted class

The diagonal cells show correct predictions.

Off-diagonal cells show mistakes.

---

### What a strong confusion matrix looks like

- Most counts are on the diagonal
- Very few counts appear outside the diagonal

That means the classifier is usually predicting the correct class.

---

### What this helps you discuss

The confusion matrix is useful because it does not just say “accuracy is high.”

It tells you:

- exactly which classes confuse the model
- whether one class is commonly mistaken for another
- whether errors are isolated or systematic

For your project, the matrix should show that mistakes are rare and concentrated in only a small number of cases.

## 10. How to Present the Results in a Discussion

You can explain them in this order:

1. Start with the dataset verification results
   - show class distribution
   - show sample images

2. Move to training behavior
   - explain training curves
   - mention validation monitoring and early stopping

3. End with final model performance
   - report accuracy
   - explain precision, recall, F1-score
   - show confusion matrix
   - discuss sample predictions

This creates a clean story from raw data to final deployed model.
